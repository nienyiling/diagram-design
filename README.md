# 公務用圖表工具

**填表格，程式幫你畫圖。** 九種產生器（流程圖、泳道圖、組織圖、**關係圖**、**家系圖**、甘特圖、時間軸、
分層堆疊圖、四象限圖）：你決定有幾列、每一列寫什麼、哪裡分岔、誰是誰的父母；
方塊多大、線怎麼連、符號怎麼畫由程式算。**下載的 Word 檔裡，圖還能在 Word 裡改**。
另附 153 張排好版的範本可以挑來改字（首頁預設收起來）。

流程圖與關係圖另外有一種畫法：**畫板**——自己拖形狀、自己連線、改大小顏色，
**線會黏在形狀上**。填表產生的圖可以整張搬進畫板繼續微調。入口在那兩支的填表畫面裡
（它就是「自己畫」，不是另一種圖，所以不佔首頁一格）。

純靜態、純前端、零對外連線。所有運算都在使用者自己的瀏覽器裡跑，沒有後端、沒有追蹤、不呼叫 LLM。
**產生器完全不靠 AI**——使用者填表時結構就已經給定了，剩下的只是算術。

## 九種產生器（`#/make/<類型>`）

| 產生器 | 你填的一列是 | 你決定的 | 程式算的 |
|---|---|---|---|
| 流程圖 | 一個步驟 | 型別（開始／步驟／判斷／分支步驟／結束）、文字、副標、往右岔幾步、退回哪一步 | 方塊大小、位置、連線、分支怎麼繞回主線 |
| 泳道圖 | 一個步驟 | 負責單位、步驟、順序 | 泳道怎麼分、步驟落在哪一格、交接的斜線 |
| 組織圖 | 一個單位 | 單位名稱、小字、上級是誰 | 樹狀排版：葉子由左而右、父節點置中、太寬自動縮小 |
| 關係圖 | 一個方塊／一條連線 | 直式／橫式、每列（欄）幾個；方塊的字、框線實虛、底色；線的實虛、箭頭、線上的字 | 方塊大小、折行、排列、線怎麼繞、線上的字放哪 |
| 家系圖 | 一個成員／一段關係 | 姓名、性別、年齡、父母是誰、婚姻狀態、情感關係 | 世代、手足位置、伴侶線、子女線、符號與情感關係線 |
| 甘特圖 | 一項工作 | 名稱、起迄日、階段、是不是查核點 | 時間軸刻度、長條的位置與長度、標籤放左邊還右邊 |
| 時間軸 | 一個事件 | 日期、事件、說明、重不重要 | 脊線、圓點、等距排列 |
| 分層堆疊圖 | 一層 | 層名、內容、是不是重點層 | 每一層的高度與位置 |
| 四象限圖 | 一個項目 | 名稱、兩個軸各 1–5 分、是不是重點 | 落點座標、同一格的項目怎麼疊開 |

共通的部分：

- **日期一律吃得下民國年**：`114/3/5`、`114.3.5`、`114年3月5日`、`1140305`、全形數字都認得，
  西元 `2025-03-05`、`20250305` 也可以。看不懂就講得出是哪一項、打了什麼、可以怎麼打。
- **填錯不會靜靜少畫一塊**。每一種錯（日期看不懂、迄日早於起日、退回目標指不到、上級指到後面、
  分支後面沒有主線可以匯回、某一列沒填主要文字）都有一句看得見的提醒，講得出是第幾列、打了什麼。
- **不給逐段改字**。表單是唯一真相；兩個地方都能改字的話，
  使用者改完表單會發現剛才在下面改的字被蓋掉，那更難用。
- **換配色、換字體、下載與複製到剪貼簿跟範本庫走同一條路**，
  所以產生器畫出來的圖跟挑來的範本看起來是一家人。**字體預設標楷體**（公文就是標楷體）。

首頁最上面就是這九個入口，每一個都附一張縮圖——那張縮圖是**產生器拿自己的範例當場畫出來的**，
不是範本、也不是圖片檔。看到什麼形狀，填完自己的內容就會得到什麼形狀。

### 流程圖的分支

判斷底下接幾列「分支步驟」，就是往右岔出去的那一路。可以連走好幾步，走完自動匯回主線——
真實的公文流程幾乎都是這樣，「分岔出去只有一格」是畫不出來的。
分支不想回主線（例如「移文他科」就結案了），把判斷那列的「分支不回主線」勾起來，
最後一格會畫成圓角收尾。三條線的字（往右、往下、退回）各自有欄位，
往下那條留空的話會自動標成往右那條的相反詞（是↔否）。

### 關係圖（公文與簡報裡那種「示意圖」）

方塊裡寫字、中間拉線、線上再寫一句話——比較各職域、比較修法前後、畫出誰跟誰有關係，
公文附件最常出現的就是這種圖。**方塊可以實線、虛線或不畫框**，
**線可以實線、虛線，可以單向箭頭、雙向箭頭或不加箭頭**，線上可以寫字。

一張表分兩段：**先填方塊，方塊填夠兩個才輪到連線**（沒有方塊就沒有東西可以連）。

**直式或橫式自己選**：直式是由左而右排、排滿一列換下一列；橫式是由上而下排、排滿一欄換下一欄。
「每列（欄）幾個」自己填，留空就自動；某一個方塊想提早換到下一列（欄）就勾「另起一列」。
**橫式一欄一個**就是一條由左而右的鏈——公文附件裡的「作業流程示意」多半長這樣。
橫式的每一欄會垂直置中對齊，短的那一欄不會吊在上面。

文字太長會自動折行；想自己決定在哪裡斷，就在要斷的地方打一個「/」。

同一列的兩個方塊之間如果有線、線上又有字，欄距會自動讓開到放得下那句話——
不然「體制內不衡平」會擠在兩個方塊中間的縫裡，兩邊都壓到框線上。

### 家系圖（社工用的 genogram）

社工做家訪、寫評估報告要畫的那種。符號照 McGoldrick 那一套通用慣例：

| | |
|---|---|
| 成員 | 男 □、女 ○、性別不明 ◇；**案主雙框**（強調色）、**已歿打叉**；年齡在符號裡、姓名在下面 |
| 伴侶 | 橫線接兩個人，一男一女時**男左女右**（同性伴侶照填的順序）；結婚實線、同居虛線；**分居一撇、離婚兩撇**；線上標狀態與年份 |
| 子女 | 從伴侶線中點垂下，長子在左；**親生實線、收養虛線、寄養點線** |
| 情感關係 | 另外一層，用強調色**走弧線**：親近雙線、非常親近三線、疏遠虛線、衝突鋸齒、斷絕兩撇、暴力鋸齒加箭頭 |

**一張表就填得完**：一列可以是「成員」「伴侶關係」或「情感關係」，用最左邊的型別欄分。
成員只要填「父親是誰、母親是誰」，**世代與手足位置由程式算**——社工填的時候一個一個人
往下加就好，不必自己想版面。父母只能選前面已經填過的成員（不然會繞成圈）。

**後兩種列不是人**，只是把兩個「已經填過的成員」連起來（欄位是「伴侶／和哪一位／狀態／年份」），
所以那兩種列沒有姓名、性別、年齡欄——性別是掛在成員那一列上的，一個人只填一次。
同性伴侶照樣畫得出來：符號各依各自的性別，位置照你填的順序。

有共同子女卻忘了填伴侶關係時，照樣會畫一條線（不標「結婚」），不然子女會憑空垂下來。
情感關係走弧線是刻意的：跟結構線（伴侶線、子女線）分得開，也比較不會從別人的符號正中間穿過去。
**再婚不必自己排位置**：結過兩次以上的那一位會自動排到中間，前一段婚姻在左、後面的在右，
兩條婚姻線各自接隔壁，不會從前任身上跨過去。結過三次以上時中間一定卡著人，
那條線會**繞到符號上面走**，子女線也改從空隙垂下來。
**線還是可能交叉**——成員一多就避不掉，那時候把某一位的位置往旁邊調（改填的順序）通常就解決了。

### 一張表分兩段：先填東西，再拉關係

關係圖與家系圖都是「一列可以是好幾種東西」。全部混在一條長表裡時，
使用者看到的是「一列一列長得都不一樣」，第一個問的就是「這是什麼意思」。
所以這兩種分成兩個區塊：上面填**方塊／成員**，下面填**連線／關係**，
**各自一顆「＋」**，而且**上面填夠兩個之前，下面的「＋」是關起來的**（旁邊寫著為什麼）。

編號從各自那一段數起：關係區塊的第一列就寫 1，不是 8。上移下移只在自己那一段裡動。

### 不會白做工

| | |
|---|---|
| 刪錯一列 | 按「復原」就回來（記 30 步）。刪除、清空、貼上、載入設定檔都進得了復原 |
| 關掉分頁 | 填的內容留在這台電腦的瀏覽器裡（localStorage，純本機、不上傳），再開還在 |
| 下個月要再送一次 | 「存出設定檔」存的是你填的內容（一個小小的 .json），載入就接著改，也能傳給同事 |
| 內容已經在 Excel 裡 | 選一塊複製，貼進「從 Excel 貼一整塊」——一行一列、一個 Tab 一欄，可取代或接在後面 |

## 畫板：流程圖與關係圖的另一種畫法（`#/board`）

填表產生的版面是程式排的，排得整齊但形狀固定。真實的公文流程偶爾就是有一格要擺在別的地方、
或要多一個註記框。所以那兩支另外有一種畫法。

搬過去之後畫板會記得自己是從哪一種來的：標題、麵包屑與「回填表畫面」都指回原本那一種，
重開分頁也還記得。**關係圖搬過去會掉一點東西**：畫板的線只有單向箭頭，雙向會變單向、
「不加箭頭」也會長出箭頭，按下去之前會先問一聲。

**畫板不是另一種圖，它就是「自己畫」**，所以入口在流程圖與關係圖的填表畫面裡，
不佔首頁一格。那裡有兩顆按鈕：「把這張圖搬到畫板繼續改」與「開空白畫板自己畫」。

**定位是「程式先排好，你再微調」，不是「從空白開始畫」。**
從空白開始畫流程圖，跟在 Word 裡拉方塊一樣痛苦——那正是這個站要解決的問題。
所以建議走第一顆：先填一填讓程式排好，再搬過去微調，搬過去之後每一格都拖得動。
畫板裡也留了一條回填表畫面的路。

| 做得到 | 怎麼做 |
|---|---|
| 加形狀 | 點工具列（步驟、起訖、判斷、註記、純文字）。連按會**往下排**，不會疊在一起 |
| 移動 | 直接拖。放開時對到 10px 的格線，所以拖出來的東西是齊的 |
| 改大小 | 選取後拖角落或邊上的把手（八個），有最小尺寸，拉不成一條線 |
| 連線 | 點「連線」→ 點起點 → 點終點。**線黏在形狀上**，之後拖動方塊時線會跟著跑 |
| 線上標字、虛線 | 選取形狀，右邊會列出它身上的每一條線，可以改字、切虛線、刪掉 |
| 改字、改形狀、改顏色、改字級 | 選取後在右邊改 |
| 鍵盤 | 方向鍵推一格（Shift 推五格）、Delete 刪掉、Esc 取消選取 |
| 不會白做工 | 復原 40 步、內容留在瀏覽器裡、存出／載入畫板設定檔 |

幾個刻意的取捨：

- **加形狀是「點一下」，不是從工具列拖進來。** HTML5 的 drag-and-drop 在觸控裝置上不會動，
  而使用者有一半是拿平板或手機開的。點一下放到定位、再拖走，步驟一樣少而且到處都能用。
- **連線是點兩下（先起點、再終點）**，不是從邊緣的小圓點拉出來——那種小圓點在手機上按不到。
- **往回接的線會繞邊走**，不會直直往上穿過中間夾著的每一個方塊。退回線幾乎都是這一種。
- **兩個方塊的中心只差一點時走直線**（30px 以內），不要轉出一個很小的階梯——
  那看起來像畫錯而不像刻意。常見成因是使用者把其中一個方塊拉寬了。
- **線上的標籤畫在所有線之上**。同一輪畫的話，後畫的線會直接壓過前一條線的標籤，
  「否」就變成看不懂的一團。
- **畫板是單向門**：填表 → 畫板可以，畫板 → 填表不行（表單記的是「一串有順序的列」，
  畫板記的是「一堆有座標的框」，回不去）。所以搬過去之前會先問一聲，
  而且填表那邊的內容會留著，隨時可以回去重新產生一次。
- **刪掉形狀時連著它的線一起走**，不然會留下指不到形狀的箭頭飄在半空。

畫板產出的圖跟填表產生的走同一條後路：同樣的色票、同樣的字體切換、同樣的下載
（Word 檔打開就能改）與複製到剪貼簿。

## 下載：Word 檔打開就能改

| 格式 | 用途 |
|---|---|
| **Word（.docx）** | **每一個方塊、每一行字都是 Word 圖案，打開直接點就能拖、改字、換顏色** |
| 複製到剪貼簿 | 按完直接到 Word 或簡報 Ctrl+V，不必先存檔 |
| PNG | 貼簡報用，可選 1／2／3 倍 |
| SVG | 向量檔，放大不糊，Word 也可以直接插入 |
| HTML | 離線開得起來，用瀏覽器列印成 PDF |

**不要按右鍵的「轉換成圖形」。** 那是 Word 自己的 SVG 轉換，實測 Word 2019 轉一張家系圖：
68 個圖形進去、51 個圖案出來，**32 段文字一段都沒留**——姓名、年齡、婚姻狀態全不見，
只剩一堆線。所以這個站不靠那一步：填表產生的圖在下載時就已經整張換成 Word 原生圖案
（DrawingML 的圖案群組），打開就是能改的狀態。

範本庫那 153 張是別人寫的任意 SVG（CSS class、漸層、巢狀 svg 都有），換不了，
仍舊以「SVG＋PNG 後備」的圖片放進去，畫面上也會照實說。

ZIP 打包器在 `core.js` 的 `zipStore()`，只做 store 不壓縮——為了幾百 KB 去長一個
壓縮器不划算，這個站的鐵律是零相依。

## 版面

- **寬螢幕（≥1180px）**：表單在左、預覽黏在右邊。改一格馬上看到。
- **窄螢幕**：預覽搬到表單「上面」並黏在畫面頂端。放在下面的話它永遠在畫面外，
  「改一格馬上看到」就等於沒有——那是這個工具唯一的賣點。
- **手機（≤719px）**：一列＝一張卡，主要文字獨佔一行、其餘兩兩並排。
  不這樣做的話七個欄位各佔一行，七個工作項目就是一條七千像素的長龍。

## 153 張範本：挑一張改字（首頁預設收起來）

| | |
|---|---|
| 能改 | 圖上每一段文字、標題與眉標、四個主要顏色、整張圖的字體（含標楷體） |
| 不能改 | 方塊的位置與大小、線怎麼連——那是範本畫死的 |
| 輸出 | 複製到剪貼簿直接 Ctrl+V、PNG、SVG（向量）、HTML（離線開、列印成 PDF） |
| 省事的地方 | 從 Excel 貼一整欄依序填入、存出／載入設定檔接著改 |

範本的限制是真的：**方塊是畫死的**，你的流程有五步而範本畫四步就沒辦法。
所以範本現在的定位是「**想知道這種圖長什麼樣子的時候看**」，不是主要的路——
用現成範本直接改字就能上的機會太小了。真的要做圖，走上面七種產生器。
首頁上它整區收在一個 `<details>` 裡，預設闔上。

**範本資料載不進來時，做圖那七種照常可以用**——它們自己算圖，不吃 `data/diagrams.json`。

**焦點放在「Excel 做不到的圖」。** 長條圖、折線圖、圓餅圖 Excel 兩下就有，
不必來這裡；真正難的是流程圖、甘特圖、組織圖這種要對齊方塊與連線的。
清單預設也只給這一類。**長條圖與折線圖仍在庫裡**，
把「只看 Excel 做不到的那種圖」取消勾選就看得到——只是不放在預設的視野裡。

## 中文層（只跟範本有關）

產生器畫出來的圖本來就是中文，這一段講的是那 153 張範本。

上游範本是英文的，而且內容是軟體專案的示範資料（Sprint velocity、OAuth、Kubernetes）。
逐字直譯對公務同仁沒有用——那些字他本來就要整段換掉。所以中文分兩層：

| 層 | 做法 | 涵蓋 |
|---|---|---|
| **公務範例**（`content/zh-samples.json`） | 人工把整張圖改寫成公務情境，不是翻譯 | 46 張、16 種圖 |
| **骨架字典**（`app/core.js` 的 `GLOSSARY`） | 圖例、月份、季別、是／否、狀態欄位這類「換掉內容之後還留在圖上」的固定用字 | 141 張都吃得到 |

合計 4,829 段裡有 1,515 段（31%）預先中文化。畫面上有「先套上中文」的開關，
有中文的預設打開；使用者自己改過的字永遠優先，切換開關不會蓋掉。

**沒有通用中文譯名的專有名詞刻意留原文**（UML、Sankey、Wardley、draw.io、Mermaid、
類別名稱、欄位名等）。硬翻成中文反而更難懂，`GLOSSARY` 查不到就回 `null`，原文保留。

已寫好公務範例的 16 種：流程圖、泳道圖、流程階段圖（跨科室流轉）、組織圖、甘特圖、時間軸、
狀態機圖、分層堆疊圖、樹狀圖、四象限、金字塔、文氏圖、長條圖、折線圖、使用者旅程圖、看板。

要再加一張：`node scripts/dump-segments.mjs <範本id>` 印出每一段與序號，
照序號寫進 `content/zh-samples.json`，再 `npm run build`。段數對不上建置會直接紅。

中文比英文寬，同樣一句話常常寬一倍。字太長時本站會自動縮小字級塞進框裡，
縮到看不清楚就代表該把字改短——這是刻意的：把字撐爆框線比縮小更糟。

用到 SVG `foreignObject` 的三張「分層資料架構圖」不能轉 PNG（瀏覽器不會把 foreignObject
畫進圖片裡），畫面上會直接停用 PNG 按鈕並說明原因，請改用 SVG 或 HTML。

## 架構

```
index.html              介面與樣式（視覺與 gongwu-calc 對齊）
app/core.js             純函式層之一：抽 SVG、換色換字體、折行、組匯出檔、流程圖版面、
                        .docx 打包（UMD，瀏覽器掛 window.DD）
app/gen.js              純函式層之二：七種產生器（填的內容 → 一整份 SVG）、貼上解析、設定檔。
                        掛 window.DDGen，只相依 core.js
app/board.js            純函式層之三：自由畫板（形狀清單 → SVG）、連線繞路、命中測試、縮放。
                        掛 window.DDBoard，只相依 core.js
app/app.js              載資料、畫做圖入口與範本列表、hash 路由（#/、#/make/<類型>、#/<範本id>）
app/editor.js           預覽與匯出的流程層：渲染、換色、換字體、自動縮字、下載、剪貼簿、設定檔
app/forms.js            產生器的畫面層：照 gen.js 的欄位規格長出表單 → gen.js 算圖 → 交給 editor 預覽與匯出
app/canvas.js           畫板的畫面層：指標事件 → 座標 → board.js 重畫。掛 window.DDCanvas
data/diagrams.json      建置產物（2 MB），153 張自足 SVG＋中文分類＋中文層。commit 進 repo，部署時直接送上去
content/zh-samples.json 人工寫的公務情境中文範例（建置來源，不部署）
scripts/build-data.mjs  vendor/upstream/*.html ＋ content/zh-samples.json → data/diagrams.json
scripts/dump-segments.mjs  印出一張圖的每一段文字與序號，寫中文範例時用
vendor/upstream/         上游範例圖的原樣副本＋LICENSE＋SOURCE.json（只在建置時用，不部署）
```

改了 `app/core.js` 的轉換規則，就要重跑 `npm run build`。忘了跑的話 `npm run test:unit`
會直接紅——`tests/data.mjs` 會重跑一次建置並跟 commit 進來的 JSON 逐字比對。

## 測試（推上去前必做，沒有例外）

| 指令 | 內容 |
|---|---|
| `npm test` | 全部：`core.unit`（160）＋`gen.unit`（100）＋`board.unit`（35）＋`data`（25）＋`e2e`（124），約 4 分鐘 |
| `npm run test:unit` | 純函式＋資料一致性，約 3 秒 |
| `npm run test:e2e` | 真的開 Chromium 點按鈕、真的下載檔案 |
| `npm run build` | 重新產生 `data/diagrams.json` |
| `npm start` | 起一個本機伺服器，印出網址 |

- 單元測試直接 `require` 站上那份 `app/core.js`、`app/gen.js` 與 `app/board.js`，**不做副本**——
  副本會跟站上的碼悄悄走鐘，「測試全過但測的是舊碼」比沒測試更危險。
- `board.unit` 最要緊的一項是「**移動形狀之後線的端點跟著跑**」——那是畫板存在的前提。
  e2e 也有一項真的用滑鼠拖，然後比對線的終點有沒有落在移動後的方塊上。
- 家系圖那一段測的是**符號慣例有沒有守住**（男方女圓、案主雙框、已歿打叉、分居一撇離婚兩撇、
  收養虛線…），不是版面好不好看——畫錯符號等於畫錯意思，那是這種圖的全部價值。
- `gen.unit` 測的是「填什麼就得到什麼」與「填錯時有沒有講人話」，不測座標——
  座標調版面時本來就會動，寫死了只會讓人不敢改版面。
- e2e 有一項專門攔 `page.on('request')` 驗證整趟操作沒有任何對外請求，**不要把它拿掉**，
  那是這個站存在的理由。另有一項逐一開完 153 張範本，確認每一張都畫得出來、文字都抓得到，
  並比對「畫面切出來的段數」與「純函式切出來的段數」——中文層是依序號對應的，
  兩邊切法一旦不同，中文會整批錯位，而畫面上只是「字怪怪的」，不會報錯。
- 錯誤訊息的測試一律斷言 `isVisible()`，不能只斷言 `textContent`：`.errbox` 預設 `display:none`，
  只塞文字不加 `.show` 會被 CSS 蓋掉，使用者一次都看不到。
- **不能用 `file://` 開來測**：站上的資料是 `fetch()` 拿的，`file://` 底下會被瀏覽器擋。
  測試自己起一個隨機埠的靜態伺服器（`tests/helpers.mjs` 的 `serve()`）。
- playwright 只裝在全域也沒關係，`tests/helpers.mjs` 會自己找。

## 部署

**push 到 main 就上線。** 有兩條路，二選一，設好一次就不用再管：

### (a) Cloudflare 後台的 Git 整合（不必弄 token）

Cloudflare 自己來拉 repo、自己建置。在 Cloudflare Dashboard →
**Workers & Pages → Create → Pages → Connect to Git**，選這個 repo，然後：

| 欄位 | 填什麼 |
|---|---|
| Framework preset | None |
| Build command | `npm run dist` |
| Build output directory | `dist` |
| Production branch | `main` |

按 Save and Deploy。之後每次推 main 就會自動重新建置上線。
**正式網址在部署完成的頁面上**——Pages 子網域全球唯一，撞名會自動加後綴
（dayoff → `dayoff-ala.pages.dev` 就是這樣來的），所以不要用猜的、也不要寫死在任何地方。

這條路底下 `.github/workflows/deploy.yml` 仍然會跑測試，只是**部署那幾步會自己跳過**
（沒有憑證），Actions 顯示綠色並在摘要裡說明。

### (b) GitHub Actions 自己部署（要 token）

走 `.github/workflows/deploy.yml`（測試 → `npm run dist` → `wrangler pages deploy`），
跟 `nienyiling/Pdftoword`、`nienyiling/dayoff` 同一個模式。

- 憑證是 repo secret：`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`。
  GitHub 的 secret 每個 repo 各自獨立，**別的 repo 設過不等於這個 repo 有**，新 repo 要再設一次：
  <https://github.com/nienyiling/diagram-design/settings/secrets/actions/new>
- token 在 Cloudflare Dashboard → My Profile → API Tokens → Create Token →
  用 **Edit Cloudflare Workers** 範本（含 Pages 權限）；Account ID 在 Workers & Pages 的右欄。
- **兩條路不要同時開**，會互相蓋掉部署。

### 兩條路共用的部分

- 部署包由 `npm run dist` 組出來（`scripts/dist.mjs`），只放 `index.html`、`_headers`、`app/`、`data/`。
  `vendor/upstream/`（建置來源）、`tests/`、`scripts/`、`content/` 都不上 CDN。
  **清單只有一份**，缺檔就讓建置失敗——少了 `data/diagrams.json` 首頁完全正常，
  只是一張範本都沒有，要等使用者真的點下去才發現。
  **新增 `app/*.js` 時要同步加進 `scripts/dist.mjs` 的 `REQUIRED`。**
- Pages 專案的 production branch 寫死 `main`，不要用 `default_branch`：那個值只在專案建立當下生效，
  之後只能到 Cloudflare 後台改，弄錯的話推 main 會全部變成 preview 部署。
- 網址不要寫死在任何地方：Pages 子網域全球唯一，撞名會自動加後綴
  （dayoff → `dayoff-ala.pages.dev` 就是這樣來的），一律從 Actions 的摘要讀。
- 快取規則在根目錄的 `_headers`。`data/diagrams.json` 檔名固定、內容會換，
  所以給的是 `must-revalidate` 而不是長快取——給 immutable 的話改過的範本永遠送不到老使用者手上。
- **驗收不能只看首頁開不開得起來**：請進一支產生器（例如甘特圖）、改一格字、加一列、
  真的下載一次 PNG 與一次 Word 檔，確認圖跟著改了、下方有來源標註。
  **Word 檔要真的用 Word 打開，並且試一次「轉換成圖形」**——這一步在 CI 裡驗不了
  （測試只驗得了 .docx 的封裝是合法的 OOXML）。範本那條路也點一張看看。
